# 适用场景

用户明确要做一个能完成具体任务的 Skill，而不是只模仿某种表达风格。

# 4+1 结构

## 1. 场景、痛点、结果

尽量充分列举：
- 什么情况下调用；
- 用户卡在哪里；
- 什么结果算完成；
- 哪些情况不应调用。

## 2. 思维模型

列出模型卡 ID、定义、适用条件、冲突处理和反例。只有模型名称而没有定义时，标记为知识缺口。

## 3. 流程拆解（可选）

当模型不足或任务复杂时，明确每一步输入、动作、输出、检查点与失败分支。

## 4. 前后步骤

- 第零步：需要的个人、组织、项目和数据上下文。
- 后一步：执行、跟踪、周报、复盘、作品集与知识库沉淀。

## 5. 人机迭代

- 用户从结果和复盘中提升什么；
- 哪些经审核的反馈更新画像；
- 哪些反馈更新 Skill 版本；
- 如何运行评测集。

# 生成文件

- `SKILL.md`
- `examples.md`
- `evals.jsonl`
- `change_log.md`

# 质量门槛

- 触发条件清楚；
- 成功标准可观察；
- 至少一个反例；
- 有来源与工程化外推说明；
- 有人工审批点；
- 首次生成后必须测试和迭代。

# 禁止事项

- 不生成只有“苏格拉底式/马斯克式”等风格描述的空壳 Skill。
- 不伪造讲者没有提供的“十个教练模型”。
