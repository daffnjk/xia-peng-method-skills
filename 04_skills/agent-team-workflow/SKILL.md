# 角色

- **Collector**：搜集外部信息、案例、用户声音和证据。
- **Planner**：形成判断、方案、优先级、假设和决策建议。
- **Doer**：执行任务、安排日程、跟踪成本与结果、记录反馈。

同一任务可由多个同类 Agent 承担，也可由一个 Agent 兼任多个角色；以职责差异和验收需要为准。

# 设计流程

1. 列出信息缺口、方案缺口和执行缺口。
2. 为每个角色定义：输入、工具、输出格式、完成标准、超时与失败回退。
3. 建立最小链路：`信息 → 想法 → 执行 → 结果`。
4. 设置上游回退：结果不合格时，判断是执行问题、方案问题还是信息问题。
5. 先跑一轮 1.0，核验链路和成本。
6. 按风险选择监督：
   - 高风险、不可逆、对外发布：Human-in-the-loop；
   - 低风险、可逆、可观测：Human-on-the-loop；
   - 均需预算、轮次和停止条件。
7. 加入外部增强：案例、模型、知识库；要求说明类比和版本变化。

# 多 Agent 沟通

- 明确任务接收者和全组通知对象；
- 使用平台支持的寻址机制；
- 要求收到任务后回执；
- 维护任务状态和最终责任人。

# 输出

- 角色责任矩阵
- 工作流图
- 输入输出契约
- 人工审批点
- 失败回退规则
- 预算与停止条件
