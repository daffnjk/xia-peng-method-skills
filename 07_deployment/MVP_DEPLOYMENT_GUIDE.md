## 1. 产品边界

使用“夏鹏智能体方法论助手（非官方）”等明确非官方的名称，不冒充本人或声称已获授权。当前证据覆盖 `XP-T-001`—`XP-T-004`，包括智能体工作方法和职业规划，但不是其完整思想体系。

部署前核对 [来源清单](../01_source/manifest.csv)：前三个来源的授权尚未记录，职业规划来源仅按内部使用、待确认处理。以下是技术配置说明，不构成对外发布、上传第三方服务或课程再分发的授权。先确认目标环境符合资料使用范围。

## 3. 两种接入方式

**Codex 本地项目**：打开完整仓库根目录，使用 `AGENTS.md` 与 `.agents/skills/`，按 [Codex 指南](../README_CODEX.md) 验证技能发现。运行维护脚本不需要启动额外 Web 服务。

**其他智能体平台**：将系统提示词放入系统指令，把来源、知识卡和治理文件分别配置为可检索资料；按宿主支持的方式将 Skill 转为技能或工作流，显式接入路由。不能假定平台会自动扫描本仓库目录，文件格式、检索能力、模型、持久化和工具权限均需在目标环境验证。

本仓库不提供向量数据库、索引构建器、托管 API、模型调用后端或多 Agent 自动调度器。Collector / Planner / Doer 是工作流设计约定，不等于已经部署运行的三个服务。

## 4. 知识分层与检索

使用四层：来源证据、原则、案例、治理。推荐流程为：原则/案例检索 → 原稿回查 → 按需要核对模型/冲突/风险审计 → 生成答案 → 检查来源和边界。高风险问题必须检查治理资料，不能因检索排序而忽略它们。

文件清单与格式见 [知识上传顺序](KNOWLEDGE_UPLOAD_ORDER.md)。个人画像放在独立、经授权的上下文中，不进入课程知识库。课程授权不自动覆盖个人资料授权。

## 5. 验收、日志与发布

先执行基础检查和同步检查，再按 [评测说明](../06_evals/README.md) 做模型行为回归。验收应覆盖来源复现、场景 Skill、职业规划、个人资料边界、拒绝冒充、缺失模型不编造、多 Agent 审批和收益不保证。

记录实际 commit、宿主/模型、检索配置、问题、证据、回答、评分和反馈；敏感内容最小化并按授权范围保存。没有行为测试结果时，不将部署状态描述为“生产就绪”。

对外发布、资金操作、招聘决策或其他高影响动作设置人工审核，不将建议自动等同于授权执行。发布前完成 [发布清单](../08_ops/RELEASE_CHECKLIST.md)，保留已知可用 commit 与目标环境配置；回退以经过验收的版本为准，而不是只回退文档。
