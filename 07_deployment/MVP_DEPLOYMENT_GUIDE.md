# MVP 接入与能力边界

项目是非官方方法论资产库，不是完整人物分身或独立服务。推荐先使用完整仓库或构建出的内部运行包接入现有宿主，不提前引入多用户后端、向量数据库和调度系统。

先安装 requirements-dev.txt，执行 validate、单元测试、build 和 validate --check-build。生成系统提示词、注册 Skill、知识和证据文件的接入顺序见 KNOWLEDGE_UPLOAD_ORDER.md。只复制单个 Skill 文件夹不等于拥有它依赖的共享规则和来源。

宿主负责模型调用、文件读取、授权个人上下文、网络访问与动作审批。本仓库不提供检索器或工作流执行器；agent-team-workflow 只设计角色与契约，不自带调度运行。

首次验收检查非官方身份、文件级/段落级引用、缺失十模型、画像关闭、复合任务分流、当前事实缺少工具时的降级，以及高风险动作审批。必须在固定资产版本下保存实际回答和检索依据，详见 06_evals/README.md。

内部包也不代表所有材料已经获准使用。公共分发必须通过 strict evidence、明确授权、同版本行为报告与命名审批；当前历史来源精确映射及授权未完成时，应被阻止，不应通过修改标记来绕过。
