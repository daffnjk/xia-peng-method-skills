# 夏鹏智能体｜新课程增量接入 SOP

## 一、核心原则

新课程不是“直接喂给智能体”，而是先作为证据进入暂存区，再经过校对、结构化提取、差异合并、冲突审查和回归评测，最后随新版本发布。

```text
新稿件
  ↓
来源登记与权限确认
  ↓
保留原稿 + 保守校对 + 稳定锚点
  ↓
提取原则 / 模型 / 案例 / 风险主张 / Skill 候选
  ↓
与现有知识做差异合并
  ↓
更新 System Prompt / Router / Skills（仅在必要时）
  ↓
新增评测 + 全量回归
  ↓
发布新版本并保留回滚点
```

## 二、每次至少提供什么

最小材料包：

1. 逐字稿原文件；
2. 课程标题；
3. 属于哪个系列或第几讲；
4. 大致录制/发布顺序；
5. 是否允许用于对外产品。

理想材料包再增加：原视频或音频、时间码、PPT/讲义、课程中演示的 Word/PDF/Skill 文件、课后作业和真实结果。

只有逐字稿也可以处理，但专有名词、语气和观点变化的核验能力会降低。未知信息保留未知，不能据此推定授权；登记模板见 [NEW_COURSE_INTAKE_TEMPLATE.yaml](NEW_COURSE_INTAKE_TEMPLATE.yaml)。

## 三、来源编号与不可变规则

- 新课程 ID 以 `01_source/manifest.csv` 中已登记的最大编号为基准自动递增，不硬编码“下一个 ID”。当前 `XP-T-004` 已用于职业规划，不可复用；若清单没有后续来源，下一条才是 `XP-T-005`。
- 原始文件永久只读，任何校对都写入新文件。
- 已发布的 source ID、段落锚点和卡片 ID 不重新编号。
- 同一课程修订使用 `source_version`，例如 `1.0 → 1.1`，不创建假装全新的课程。
- 同一课程的补充讲义可用附件 ID，例如 `XP-T-004-A01`。

## 四、八步接入流程

### 第 1 步：登记

在 `01_source/manifest.csv` 增加一行，记录标题、系列、时间、文件、授权、状态和版本。优先运行脚本自动分配下一个 ID，不要先手动添加一行再重复执行登记脚本。先确认原文件存在、清单中没有同一课程，并明确授权范围。

```bash
python3 scripts/scaffold_new_course.py \
  --title "绩效管理课" \
  --series "管理者课程" \
  --session "第4讲" \
  --transcript "/path/to/transcript.txt"
```

以上标题、系列和路径均为示例，应替换成实际信息。脚本只创建收件箱文件并登记 manifest，不会自动校对原稿、更新知识、生成 Skill 或完成评测；默认授权状态 `not_recorded` 不代表获准发布。

### 第 2 步：保守校对

只修高置信度问题：错别字、明显 ASR 错误、统一人名和缩写。不可确定的专有名词不猜，进入 `uncertain_terms.md`。保留 `correction_log.csv`，使任何修改可追溯。

### 第 3 步：语义切片与来源锚点

按完整观点、判断、案例或步骤切片，不按固定字数机械截断。以下以尚未接入的假想 `XP-T-005` 演示格式；实际使用登记后的 ID，不得与现有来源重复。

```text
[XP-T-005#P001]
课程原文……
```

有视频时间码时同时保留：

```text
[XP-T-005#P001 | 00:03:12–00:05:08]
```

只有真正写入并核对过的锚点才能用于精确引用。当前 XP-T-001—003 的历史标号映射仍需补齐，不得套用示例编号制造引用。

### 第 4 步：提取六类候选资产

1. 原则候选：讲者明确提出的判断规律；
2. 模型候选：模型名称、定义、适用条件、步骤和反例；
3. 案例候选：背景、输入、判断、行动、结果和局限；
4. Skill 候选：可重复解决某个场景问题的方法；
5. 冲突候选：与旧材料口径不同或条件发生变化；
6. 风险主张：价格、平台能力、预测、收益、贬损和营销表达。

### 第 5 步：与旧知识做差异合并

逐条使用 [MERGE_DECISION_MATRIX.md](MERGE_DECISION_MATRIX.md)。最重要的规则是：

- 同义内容只补来源，不重复建卡；
- 更完整的内容扩写旧卡，并保留变更记录；
- 新旧观点冲突时同时保留，不覆盖；
- 只有模型名、没有定义时，只更新模型登记；
- 一次性故事先进入案例卡，不急于上升为原则；
- 营销与平台主张进入治理层，不进入人格核心。

### 第 6 步：决定是否更新智能体或 Skill

不是每门新课都要改 System Prompt 或新增 Skill。

- 只补证据：更新原则/案例来源即可；
- 细化旧方法：升级对应 Skill 的 patch/minor 版本；
- 改变方法行为：升级 major 版本并增加迁移说明；
- 扩展新领域：更新 System Prompt、AGENTS.md 的材料边界和 Router，并建立新 Skill；
- 只增加案例：通常不改 Prompt。

共享方法论 Skill 按 [贡献指南](../CONTRIBUTING.md) 在 `04_skills/` 维护，审阅后同步到 `.agents/skills/`，两处一起提交。运行目录独有资源需要单独审阅，不能依赖同步脚本自动删除或合并。

Skill 版本建议：

```text
0.1.0 → 0.1.1  文案、来源、边界小修
0.1.0 → 0.2.0  新增流程、模型或输出能力，基本兼容
0.x   → 1.0.0  经完整评测后进入稳定版
1.x   → 2.0.0  核心判断方式或输入输出契约不兼容
```

### 第 7 步：新增评测并做全量回归

每门课至少新增：

- 3 道来源复现题；
- 2 道新场景迁移题；
- 2 道边界/反诱导题；
- 发现观点冲突时，再加 1—2 道冲突题；
- 新建 Skill 时，至少再加 5 道该 Skill 的功能题。

发布前不仅跑新题，也要跑全部旧题，防止“学了新课，忘了旧规则”。执行与记录方式见 [评测说明](../06_evals/README.md)；文件检查和 Python 单元测试不能替代模型行为回归。

### 第 8 步：发布与回滚

- 从明确的 Git commit 构建候选版本，在测试环境验收；
- 完成 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)，通过审核和评测后再确定正式版本；
- 记录新增来源、更新卡片、变更 Skill、兼容性、已知问题与实际测试结果；
- 保留上一版 commit、对应版本包和外部索引/配置（如有），出现问题可以回滚；
- 未确认授权、未解决关键来源/边界失败或未完成必要验收时，不对外发布。

## 五、一个具体例子

假设未来接入 `XP-T-005`“绩效管理课”。以下全为合并判断示例，不表示已经收到该课程，也不表示其实际讲过这些内容：

1. 课程再次讲目标管理，但只是重复 SMART、OKR：给现有原则和模型卡补来源，不新建 Skill。
2. 课程第一次详细解释 GRAI：核对定义后，把 `model_registry.yaml` 中相应条目升级为 `source_defined`，增加步骤和适用条件。
3. 课程给出三个真实绩效案例：新增案例卡，其中失败案例必须保留。
4. 课程说“周报不应每周做，而应按项目节奏做”：进入冲突/演化记录，判断适用条件，不直接覆盖旧观点。
5. 课程形成一套独立绩效面谈流程：满足门槛后新建 `performance-review/SKILL.md`，并更新 Router。
6. 新增评测、全量回归并审阅后，再确定发布版本，不提前把示例版本写成已发布。

## 六、建议的批处理节奏

- 单篇重要课程：单独发布一个候选版本；
- 同一系列的零散短稿：每 3—5 篇作为一批处理；
- 每累计约 10 门课：重新审视主题分类和思维地图；
- 每新增一个完整领域：单独建立领域目录和评测子集，避免一个超级 Prompt 无限膨胀。
