# 新课程知识合并决策表

新课程提取后，逐条候选内容按下表处理。禁止把新稿直接整份覆盖旧知识。

| 新内容类型 | 判断标准 | 合并动作 | 是否改 System Prompt / Skill |
|---|---|---|---|
| 重复表述 | 与现有原则含义、条件和边界基本一致 | 不新建原则卡；给旧卡增加 `source_refs`，必要时提高置信度 | 通常不改 |
| 证据补强 | 同一原则出现更完整解释、案例或反例 | 更新旧卡的步骤、适用条件、边界；保留修订记录 | 若影响执行细节，Skill 做 patch/minor 更新 |
| 条件细化 | 结论相同，但行业、阶段、角色或前提不同 | 在旧卡增加 `applicable_conditions`；差异较大时拆成子原则 | 可能更新路由或 Skill 触发条件 |
| 观点修正 | 新材料明确调整、否定或替代旧观点 | 不删除旧内容；写入 `contradictions.yaml` 或观点演化记录，并注明日期与条件 | 更新 System Prompt 的冲突处理；Skill 可能 major 更新 |
| 全新方法 | 有明确场景、判断模型/流程、输入输出和边界 | 新建原则卡、模型卡、案例卡；满足门槛后再建 Skill | 新领域才更新路由和材料边界 |
| 单个案例 | 主要是一次演示或故事，未形成稳定原则 | 新建案例卡；不要强行抽象成普遍规律 | 通常不改 |
| 只提模型名 | 只出现 SMART、MVP 等名称，没有夏鹏自己的定义 | 更新 `model_registry.yaml` 为 `external_definition_required` / `partially_observed`，不得自行补定义 | Skill 只能引用为外部模型或标记缺失 |
| 营销/预测/平台比较 | 涉及价格、性能、就业淘汰、收益保证、课程销售 | 写入 `claim_audit.yaml`；默认不进入核心人格与回答规则 | 通常只增强护栏 |
| 专有名词不确定 | ASR 可能识别错误，无法从上下文确定 | 写入 `uncertain_terms.md`，等待音视频核验 | 不进入关键判断 |
| 外部事实 | 公司、产品、价格、政策、统计数字 | 保留原话，但在产品回答时要求另行核验 | 增加核验规则，不把它当长期事实 |

## 建 Skill 的最低门槛

只有同时满足下列条件，才从课程内容生成或升级生产级 Skill：

1. 有清晰的调用场景与不适用场景；
2. 有可重复的判断模型或执行步骤；
3. 输入、输出和成功标准可定义；
4. 有至少一个完整案例，并能提取失败点或边界；
5. 有来源锚点；
6. 至少补充 5 道评测，其中必须有来源题、迁移题和边界题；
7. 与现有原则不存在未处理的实质冲突。
